## 1. 为什么 UI 是闭环的一部分

底层技术解决的是：

- 系统如何采集 Experience；
- 如何判断 Outcome；
- 如何提取 Candidate；
- 如何保存 Memory 和 Pattern；
- 如何在后续请求中召回和复用。

页面必须解决的是：

1. 用户是否知道系统学到了什么；
2. 用户是否理解为什么值得记住；
3. 用户是否能在学习生效前确认或修改；
4. 用户是否知道本次任务使用了哪些经验；
5. 用户是否能发现错误经验造成的影响；
6. 用户是否能停用、删除、导出和重置数据；
7. 用户是否知道哪些数据发送给了远程 Provider。

如果缺少以上界面，自动学习会变成不可见的隐性画像，用户无法建立信任，也无法为 OutcomeEvaluator 提供可靠反馈。

## 3. 设计原则

### 3.1 学习必须可见但不打扰

- 不在任务完成时强制弹 Modal；
- 会话中使用轻量提示；
- Candidate 集中进入 Inbox；
- 只有高风险冲突或敏感数据才要求即时确认。

### 3.2 自动提取不等于自动生效

- Candidate 与 Active Memory 必须有清晰视觉区分；
- Suggested Pattern 不得伪装成已经生效；
- 自动晋升必须说明原因和证据。

### 3.3 用事实指标代替虚假“聪明度”

不展示无法解释的总分，例如“聪明度 86”。展示：

- 已确认偏好数量；
- 待审核建议数量；
- 最近使用次数；
- 成功、部分成功、失败证据；
- 最近一次生效；
- 节省的重试或执行步骤。

### 3.4 渐进披露

- 默认页面使用自然语言；
- Key、fingerprint、score、embedding provider ID 等进入高级信息；
- 对话页只显示摘要，完整证据进入 Inspector 或详情页。

### 3.5 用户显式请求优先

页面应明确显示：

```text
本次请求覆盖了 1 条长期偏好
```

避免用户误以为 Memory 的优先级高于当前输入。

### 3.6 不重新发明视觉系统

- 继续使用现有 Card、Button、Tabs、Modal、ConfirmDialog；
- 继续使用现有 typography tokens；
- 图标使用 Lucide；
- 状态色复用 success、warning、destructive、muted；
- 不引入第二套页面布局或设计系统依赖。

## 5. 页面一：智能与记忆概览

### 5.1 用户目标

用户进入页面后，应在十秒内理解：

- Portico 记住了多少内容；
- 是否有待审核项目；
- 最近学到了什么；
- 是否存在失败、冲突或索引问题；
- 当前数据是否完全本地。

```text

需要处理
  - 2 条候选偏好
  - 1 条冲突

最近学到

  - 默认使用中文总结

最近使用
  - “代码修改闭环”今天使用 2 次

数据状态
  - 本地存储
  - 云端推理
  - 本地 Embedding
```

### 5.3 组件

建议新增：

```text
memory-overview.tsx
memory-overview-stats.tsx
recent-learning-list.tsx
memory-health-summary.tsx
```

### 5.4 状态

- Loading：四个一致高度 Skeleton；
- Empty：说明 Portico 尚未形成经验，并给出自然语言示例；
- Partial error：单个区域失败不阻塞整个页面；
- Privacy warning：云端 Embedding 或 Full Trace 时显示明确状态；
- Learning queue delayed：显示“学习处理稍有延迟”，不显示技术异常堆栈。

## 6. 页面二：Memory Inbox

### 6.1 页面目标

将所有需要用户决定的学习结果集中在一个地方：

- Memory Candidate；
- Suggested Pattern；
- Memory Conflict；
- Sensitive Candidate；
- 自动晋升通知。

### 6.2 筛选

```text
全部 | 偏好 | 项目约定 | 工作模式 | 冲突 | 敏感
```

附加筛选：

- Scope；
- Workspace；
- 时间；
- 置信度。

### 6.3 Candidate 卡片

默认展示：

```text
建议记住                                     高置信度

修改 Rust 代码后运行 cargo fmt 和 cargo test

推荐范围：Portico Desktop 项目
依据：最近 3 次任务中均出现相同要求

[接受] [编辑后接受] [拒绝]
```

展开后展示：

- 来源 Run；
- 原始用户表达；
- 推断理由；
- fingerprint；
- Extractor 版本；
- 是否包含敏感内容；
- 是否与已有 Memory 冲突。

### 6.4 接受流程

点击接受时，不弹完整 Modal。使用行内确认：

```text
保存到：[当前项目 v]
类型：[工作方式 v]
敏感：[ ]
[确认保存]
```

只有编辑内容、处理冲突或设置敏感时才打开 Modal。

### 6.5 拒绝流程

拒绝后提供短时 Undo：

```text
已拒绝该建议。 [撤销]
```

拒绝不要求填写原因，但可通过展开菜单选择：

- 不正确；
- 只适用于本次；
- 已有相同内容；
- 不希望 Portico 记住。

这些原因可作为 Extractor 的负向评价。

### 6.6 批量操作

第一阶段只支持：

- 批量拒绝；
- 批量移动到某个 Scope。

不支持“一键全部接受”，防止低质量长期记忆快速污染。

## 8. 页面四：工作模式

### 8.1 Pattern 列表

```text
代码修改闭环                              Active
探索 -> 实现 -> 测试 -> 总结

匹配：代码修改、Bug 修复
使用 12 次 · 成功 10 · 部分成功 1 · 失败 1

[查看详情] [编辑] [停用]
```

Suggested 使用不同操作：

```text
[接受并启用] [编辑] [拒绝]
```

### 8.2 Pattern 详情

详情采用右侧 Inspector 或 Modal，不新建页面：

- 名称与摘要；
- Status；
- 适用 Scope；
- 触发条件；
- 角色顺序；
- 协作方式；
- 工具策略；
- 输出类型；
- 成功/失败证据；
- 最近影响的 Run；
- 自动晋升原因；
- fingerprint 和版本。

### 8.3 Pattern 编辑

普通模式允许编辑：

- 名称；
- 摘要；
- 触发词；
- 是否启用；
- Scope。

高级模式允许编辑：

- 角色顺序；
- 协作方式；
- 输出类型。

不允许从该页面扩大工具权限。工具权限只能展示为只读信息，并链接到安全说明。

## 10. 页面六：数据与隐私

### 10.1 隐私模式

用三张可选择卡片，不使用模糊 Toggle：

```text
完全本地
本地模型 + 本地 Embedding，数据不发送给外部 AI Provider。

本地存储 + 云端推理
会话和长期数据保存在本地，请求上下文发送给选定模型。

云端推理 + 云端 Embedding
模型请求及参与索引的文档片段可能发送给外部 Provider。
```

切换模式前检查当前 Provider 是否满足条件；不满足时给出可操作提示。

### 10.2 学习设置

```text
自动发现候选偏好                    开
使用远程模型辅助提取                关
重复成功后自动启用工作模式          开
自动晋升门槛                        3 次
```

“自动发现”只生成 Candidate，文案中必须明确不会直接改变长期行为。

### 10.3 Trace 设置

```text
脱敏记录（推荐）
完整本地记录
仅元数据
```

每个选项展示对 Inspector、Diagnostics 和问题排查的影响。

### 10.4 数据管理

```text
导出所有个人数据
清空待审核建议
清空长期 Memory
清空 Workflow Pattern
清空 RAG 索引
重置全部学习数据
```

“重置全部学习数据”为破坏性操作，必须二次确认并明确不会删除 Workspace 源文件。

### 10.5 加密状态

展示：

- sensitive Memory 是否加密；
- Vault 是否可用；
- 是否存在待迁移明文；
- 最近迁移错误。

不要在页面展示 Keychain item、密钥引用或文件系统中的主密钥路径。

## 11. Conversation Timeline 改造

### 11.1 Assistant 消息 Footer

默认只增加一行轻量操作：

```text
[有帮助] [无帮助]    使用 3 条经验 · 2 个项目片段
```

规则：

- 只在 Run 终态后显示；
- 反馈提交后显示已选状态；
- 允许再次点击取消或修改；
- 不使用仅靠颜色表达选择状态；
- 按钮需要 `aria-pressed`。

### 11.2 使用经验 Popover

点击“使用 3 条经验”展开：

```text
本次使用
✓ 回复使用中文
✓ 修改前先扫描相关模块
✓ 修改后运行测试

项目上下文
✓ crates/app-memory/src/pattern.rs
✓ crates/app-runtime/src/context.rs

[在 Inspector 中查看完整请求]
```

### 11.3 Candidate 提示

```text
Portico 从本次任务中发现了 1 条可能值得记住的偏好。
[查看] [忽略]
```

要求：

- 不弹 Modal；
- 不抢焦点；
- 忽略只隐藏本条提示，不等于拒绝 Candidate；
- 点击查看打开 Inbox 对应 Candidate。

### 11.4 快捷“记住这个”

在用户消息和 Assistant 消息的更多菜单中加入：

```text
记住这个偏好
不要再这样做
```

点击后打开预填 Candidate 编辑框，仍需用户确认 Scope 和内容。

### 13.5 真实快照

Inspector 必须读取 Run 持久化 Snapshot，不再通过用户输入 query 重新构建当时上下文。可保留“模拟查询”作为独立开发工具，但名称必须明确为“上下文预览”。

## 14. Execution Board 补充

Execution Board 不承担完整 Memory 管理，只添加：

- 使用的 Pattern 名称；
- BehaviorPolicy 摘要；
- OutcomeSignal；
- 学习状态：Pending、Extracted、Reviewed、Failed；
- 用户反馈状态；
- “查看本次经验”入口。

单 Agent detail 示例：

```text
执行策略
中文回答 · 先探索后修改 · 修改后运行测试

经验来源
2 条已确认偏好 · 1 个 Active Pattern

任务结果
Successful · 用户标记有帮助
```

## 15. 通知与导航

### 15.1 Sidebar Badge

Memory 导航项只在存在待审核 Candidate 或 Conflict 时显示数量 Badge。

规则：

- 上限显示 `99+`；
- 已查看但未处理仍保留数量；
- 只在处理完成后减少；
- 后台学习运行中不显示 Spinner，除非用户正在 Memory 页面。

### 15.2 Notification Center

仅以下事件进入通知中心：

- 出现敏感 Candidate；
- Pattern 自动晋升；
- RAG 长期失败；
- 隐私模式与当前 Provider 冲突；
- 学习数据迁移失败。

普通 Candidate 不逐条通知，避免噪音。

## 16. 响应式布局

### Desktop >= 1280px

- Memory 中心使用主列表 + 右侧详情；
- Inspector 保持右侧面板；
- Pattern 详情不使用全屏 Modal。

### Compact Desktop 900–1279px

- 详情使用 Drawer；
- Stats 由四列降为两列；
- 筛选器允许换行。

### Narrow < 900px

- Memory Tab 横向滚动或使用 Select；
- Candidate 操作按钮纵向排列；
- 详情使用全屏 Dialog；
- 表格替换为 Card List；
- 禁止依赖 Hover 才能发现操作。

Tauri 当前以桌面为主，第一阶段不针对手机优化，但窄窗口不得出现横向不可控溢出。

## 17. 无障碍要求

### Keyboard

- 所有 Card Action 可通过 Tab 到达；
- Inbox 支持 `j/k` 可作为增强，但不能替代标准键盘导航；
- Dialog 打开后正确管理焦点；
- 关闭后焦点回到触发按钮；
- Escape 关闭非破坏性 Popover 和 Dialog。

### Screen Reader

- Status Badge 同时提供文本；
- Rating 使用 `aria-pressed`；
- Tabs 使用正确 tablist/tab/tabpanel；
- Progress 使用 `aria-valuenow`；
- 置信度不能只用颜色表达；
- sensitive 隐藏状态有明确描述。

### Visual

- 正文和背景达到 WCAG AA 对比度；
- 10px 辅助文字仅用于非关键元数据；
- 关键状态最小 12px；
- Focus Ring 不被 overflow 截断；
- destructive、warning、success 同时使用图标和文字。

### Motion

- Candidate 新增不使用强闪烁；
- 尊重 `prefers-reduced-motion`；
- 学习处理状态使用低干扰静态或轻量动画。


普通文案使用：

```text

```

## 24. E2E 黄金路径

### E2E 1：显式偏好学习

```text
用户发送“以后请用中文简洁回答”
-> Run 完成
-> 会话显示发现 Candidate
-> 打开 Inbox
-> 编辑为 User Scope
-> 接受
-> 新建 Run
-> Composer 显示将使用该偏好
-> Assistant 使用中文简洁回答
-> Inspector 显示该 Memory 已发送
```

### E2E 2：拒绝错误 Candidate

```text
生成错误 Candidate
-> 用户拒绝并选择“只适用于本次”
-> Inbox 数量减少
-> 相同 fingerprint 不再次出现
-> 后续 Run 不使用该 Candidate
```

### E2E 3：Pattern 晋升

```text
完成三次相同成功工作流
-> Suggested Pattern 去重累计
-> 自动晋升通知
-> Pattern 详情显示三条证据
-> 后续 Run 使用 Pattern
-> Execution Board 显示 Pattern 来源
```

### E2E 4：本次私密模式

```text
Composer 展开 Context Indicator
-> 开启本次私密模式
-> Memory、Pattern、RAG 被禁用
-> 发送请求
-> Inspector Snapshot 显示 DisabledForRun
-> 全局设置保持不变
```

### E2E 5：远程 Embedding 警告

```text
当前为云端 Embedding
-> 用户点击重新构建
-> ConfirmDialog 说明文件片段将发送给 Provider
-> 用户取消
-> 不启动索引
```

### E2E 6：敏感 Memory

```text
创建 sensitive Memory
-> 列表默认遮蔽
-> 云端 Run 不注入该 Memory
-> Inspector 显示 BlockedSensitive
-> Trace 不出现明文
```
